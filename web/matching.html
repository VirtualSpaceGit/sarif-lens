Matching model

Every comparison should explain itself.

SARIF Lens compares finding instances, not totals by rule. It preserves stable identity across ordinary source movement and refuses matches that are ambiguous.

Pair analysis runs

Results can match only inside paired runs. SARIF Lens tries the current run's baselineGuid against the baseline run's automationDetails.guid, then automation ID and tool name, tool name and run index, and finally a tool name that is unique on both sides.

An ambiguous run remains unpaired. Its baseline results become fixed and its current results become new.

Match results one to one

  1. 01
    Correlation GUID

    Exact producer identity.

  2. 02
    Final fingerprint

    Exact common fingerprint entry.

  3. 03
    Partial fingerprint

    High-confidence producer evidence.

  4. 04
    Snippet and path

    Normalized stable source evidence.

  5. 05
    Message and path

    Deterministic medium-confidence fallback.

  6. 06
    Path and line

    Low-confidence compatibility fallback.

Tool name and rule ID scope every key. A match is accepted only when exactly one result exists on each side of the candidate relationship. Duplicate fingerprints stay separate and produce a matching note.

Explain the delta

New

No baseline result matched.

Updated

A matched result changed in a significant field.

Fixed

No current result matched.

Unchanged

A matched result has no significant change.

Severity, message, path, snippet, CWE, and accepted suppression state are significant. Line and column changes are recorded as movement and do not make a result updated by themselves.

Line numbers come last.

An inserted comment can move many findings without changing the underlying problems. Absolute line positions are therefore never primary identity. This follows the guidance in the SARIF 2.1.0 specification.

The complete behavior, limitations, and normalized path rules are documented in docs/matching.md.
